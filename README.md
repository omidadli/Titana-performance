# استراتژی پرفورمنس مارکتینگ و CRO — تیتانا

> این مجموعه مستندات، نقشه‌ی راه کاملی است که از روز اول ورود به تیم تیتانا تا رسیدن به «زیرساخت داده‌ای کامل + فرآیند مستمر بهبود» اجرا می‌شود. هر فایل یک فاز است. **فقط یک فاز را باز کن، فقط یک فاز را اجرا کن.**

---

## ۵ قانون بازی (برای اینکه هیچ‌وقت گم نشویم)

1. **هر لحظه فقط یک فاز فعال است.** فاز بعدی فقط وقتی شروع می‌شود که چک‌لیست خروجی فاز فعلی کامل ✅ شده باشد.
2. **هر تسک باید «تعریف انجام‌شدگی» داشته باشد.** اگر نتوانستیم بگوییم چه چیزی نشان می‌دهد که کار تمام شده، آن تسک هنوز مشخص نیست.
3. **چک‌لیست مهم‌تر از تقویم است.** هفته‌های زیر «مدت معمولی» هستند؛ فاز با اتمام چک‌لیست تمام می‌شود، نه با گذشت زمان.
4. **هر کاری که امروز انجام نمی‌دهیم، «تاریخ» می‌گیرد نه «یادداشت».**
5. **هر شک فنی (اسکیم dataLayer، اسم رویداد، پارامتر) → پیوست «واژه‌گان داده» (`appendix/data-dictionary.md`). هر تسک برنامه‌نویسی → پیوست «تسک‌های تیم فنی» (`appendix/dev-tasks.md`).**

---

## نقشه‌ی راه یک صفحه‌ای

```
┌──────────────┐  ┌──────────────────┐  ┌──────────────────┐  ┌──────────────┐  ┌──────────────────┐  ┌──────────────────┐
│   فاز صفر    │→│      فاز ۱        │→│      فاز ۲        │→│    فاز ۳      │→│     فاز ۴          │→│     فاز ۵          │
│  ممیزی و     │  │    بنیان داده     │  │  داشبورد و       │  │   CRO و       │  │  پیشرفته: آفلاین،│  │  مقیاس و فرهنگ   │
│  بنیادین     │  │                  │  │  بنچمارک KPI     │  │  نرخ تبدیل   │  │  مخاطب و LTV      │  │  آزمایش مستمر    │
│  (هفته ۱-۲) │  │    (هفته ۳-۶)    │  │   (هفته ۷-۸)     │  │  (هفته ۹-۱۴) │  │   (هفته ۱۵-۲۰)    │  │     (هفته ۲۱+)    │
└──────────────┘  └──────────────────┘  └──────────────────┘  └──────────────┘  └──────────────────┘  └──────────────────┘
      «ببینیم         «داده را           «با داده تصمیم        «ترافیک هم‌اندازه،     «خرید رسانه با داده،      «سیستم همیشه‌روشن:
  کجاییم»          درست بسازیم»          بگیریم»              فروش بیشتر»          مخاطب‌سازی و LTV»          یک آزمایش در هفته»
```

**منطق زنجیره:** اول ببینیم کجاییم (۰) ← بعد داده درست جمع شود (۱) ← بعد ببینیمش (۲) ← بعد با دیدنش تبدیل را بالا ببریم (۳) ← بعد داده را روی خرید رسانه و مخاطب‌سازی خرج کنیم (۴) ← بعد مقیاس دهی و تکرار (۵).

| فاز | هدف یک‌جمله‌ای | فایل | سیگنال خروج (مهم‌ترین) |
|---|---|---|---|
| ۰ — ممیزی | بدانیم کجاییم، در یک صفحه | `strategy/01-phase-0-audit.md` | گزارش وضعیت + لیست شکاف‌ها |
| ۱ — بنیان داده | همه‌ی کارهای کلیدی سایت به GA4 + یکتانت + تپ‌سول برسد | `strategy/02-phase-1-data.md` | ۶ رویداد اصلی + اعتبارسنجی سه‌جانبه |
| ۲ — داشبورد | تصمیم‌گیری از روی یک منبع واحد | `strategy/03-phase-2-dashboard.md` | ۳ داشبورد + گزارش هفتگی منظم |
| ۳ — CRO | همان ترافیک، فروش بیشتر | `strategy/04-phase-3-cro.md` | ۴ پروژه CRO بسته‌شده با قبل/بعد |
| ۴ — پیشرفته | فروش آفلاین + مخاطب‌سازی + LTV | `strategy/05-phase-4-advanced.md` | درآمد آفلاین در GA4 + ریتارژتینگ |
| ۵ — مقیاس | بهبود مستمر به‌عنوان سیستم | `strategy/06-phase-5-scale.md` | سпрینت هفتگی آزمایش‌ها |

**پیوست‌ها:**
- `appendix/data-dictionary.md` — نام رویدادها، اسکیم dataLayer، پارامترها، استندارد UTM (مرجع فنی؛ هر بار که سوال فنی داشتی اینجا)
- `appendix/dev-tasks.md` — تمام تسک‌های تیم برنامه‌نویسی، مرتب و آماده‌ی ارسال (به تفکیک فاز و اولویت)
- `appendix/weekly-rhythm.md` — ریتم کاری روز/هفته/ماه/فصل + قالب گزارش ماهانه + چک‌لیست عیب‌یابی ۵ دقیقه‌ای
- `agents/` — **اجرای فاز ۱ با AI Agent:** پرامپت آماده برای Agent متصل به GTM و Agent متصل به GA4 (+ ترتیب اجرا و مرزهای هر Agent)

## وضعیت فعلی (خروجی مصاحبه‌ی ورودی، سپتامبر ۱۴۰۵)

| مورد | وضعیت |
|---|---|
| پلتفرم سایت | فروشگاه وب‌بیت (titana.ir) — B2B تجهیزات ایمپلنت (فیکسچر، آباتمنت، کیت جراحی، پکیج‌های حجیم) |
| GA4 + GTM | **فعال است** (کیفیت و کامل بودن آن خروجی فاز صفر می‌شود) |
| فانل فروش | **ترکیبی:** خرید آنلاین از سایت + بستن معامله با تماس تلفنی / واتساپ / تلگرام / بله |
| ترافیک پولی | **یکتانت و تپ‌سول** (بدون گوگل/متا در حال حاضر) |
| دسترسی فنی | تغییرات کدی با **تیم برنامه‌نویسی** (تسک‌ها در پیوست `dev-tasks.md` آماده‌ی ارجاع هستند) |
| نکات مهم بیزینسی | قیمت‌های «۰ تومان» = استعلامی (CTA باید «استعلام قیمت» باشد)، دانلود لیست قیمت به‌عنوان لید، دستیار هوش مصنوعی «تینا»، تحویل ۳ ساعته تهران + تسویه در محل |

**دو فانل که باید با هم سنجش شوند (نه یکی به‌عنوان اصلی):**
- **فانل E-commerce:** دیدن محصول → انتخاب سایز/مدل → سبد → چک‌اوت → پرداخت
- **فانل لید:** دیدن محصول → دانلود لیست قیمت / فرم / واتساپ / تلگرام / تماس / چتbot → تماس فروش → (فروش آفلاین)

- [ ] **فاز ۰** — ممیزی و بنیادین (گزارش وضعیت آماده شد)
- [ ] **فاز ۱** — بنیان داده (زیرساخت جمع‌آوری داده ساخته شد)
- [ ] **فاز ۲** — داشبورد و KPI (تصمیم‌گیری از روی داشبورد)
- [ ] **فاز ۳** — CRO (نرخ تبدیل با داده بالا رفت)
- [ ] **فاز ۴** — پیشرفته (فروش آفلاین + مخاطب‌سازی + LTV)
- [ ] **فاز ۵** — مقیاس (سیستم آزمایش مستمر روشن است)

## از کجا شروع کنم؟ (مسیر پیشنهادی)

1. **همین الان:** `strategy/01-phase-0-audit.md` — ۱۰ تسک، حدود ۲ هفته. خروجی‌اش یک «گزارش وضعیت» یک‌صفحه‌ای برای مدیریت است.
2. لیست شکاف‌هایی که در فاز صفر پیدا می‌کنی، **دقیقاً ورودی فاز ۱ است** — یعنی فاز ۱ از «چند چیز کلی» شروع نمی‌شود، از «چیزهایی که واقعاً خراب/نبودند» شروع می‌شود.
3. هر شک فنی → `appendix/data-dictionary.md`، هر کار فنی → `appendix/dev-tasks.md`.

**قانون طلایی ضدگیجی:** اگر وسط هر فازی احساس کردی «الان باید کجا باشم؟» — به بالا برگرد، فاز فعال را ببین، و فقط ۳ تسک برتر همان فاز (هر فایل با «۳ کار مهم‌ترین» شروع می‌شود) را انجام بده.
