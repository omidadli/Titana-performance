# ۷) استراتژی در یک صفحه (برای مدیرعامل/مدیر بازاریابی)

## تشخیص
تیتانا یک **فروشگاه B2Bِ قفل‌شده** است: خرید فقط برای دندانپزشک/کلینیک/لابراتوار، ورود با موبایل و OTP، سبد پشت لاگین، بخش بزرگی از پکیج‌ها بدون قیمت (۰ تومان → مذاکره)، و فروش قابل‌توجهی که در واتساپ/بله/تلگرام/تلفن بسته می‌شود.
در چنین مدلی، «تگ زدن روی Add to Cart و Purchase» **نمی‌تواند** بگوید کدام کمپین مشتری آورده؛ چون:
1. مسیر اصلی تبدیل، لاگین → استعلام → مذاکره → سفارش است، نه کلیک → سبد → پرداخت.
2. ارزش واقعی مشتری در **تکرار و قطعات مکمل** است، نه خرید اول.
3. بدون اتصال هویت (موبایل هش‌شده ⇄ client_id ⇄ شناسه مطب)، هر عدد ROAS یک حدس است.

## تصمیم‌های پنج‌گانه‌ی استراتژی
1. **هویت اول، کمپین بعد.** اولین چیزی که اندازه می‌گیریم قیف احراز هویت است (`login_gate_hit → otp → signup → profile → docs_verified → first_order`)، چون بزرگ‌ترین نشتی همین‌جاست.
2. **Lead-centric، نه فقط Sale-centric.** سه تبدیل کلیدی موازی: `purchase`, `quote_request` (پکیج بی‌قیمت), `tool_submit` (سفارش سریع/هوشمند/پکیج اختصاصی) + `signup`.
3. **حقیقت در انبار، نه در GA4.** GA4 برای مخاطب‌سازی و دیدِ سریع؛ درآمد/حاشیه/LTV از BigQuery با اتصال به پنل سفارش و CRM.
4. **اول‌طرف‌گرایی.** با توجه به محدودیت پلتفرم‌های تبلیغاتی برای ایران و اختلال شبکه: dataLayer استاندارد + sGTM/endpoint اول‌طرف + یک مقصد داخلی برای صحت‌سنجی حجم. تگ‌های گوگل‌ادز/متا «آماده ولی خاموش» نگه داشته می‌شوند.
5. **صفر داده‌ی بالینی.** هیچ اطلاعات بیمار/بیمار/مجوز در تگ‌ها. فقط رفتار خرید + هویت هش‌شده. (هم اخلاق، هم ریسک حقوقی.)

## چیزی که قرار است بسازیم
| لایه | تحویل |
|---|---|
| قرارداد داده | dataLayer نسخه ۱٫۰ با ۳۴ رویداد الزامی + ۲۸ پشتیبان، ۲۵ بعد + ۱۰ ویژگی کاربر (`docs/03`, `data/datalayer-schema.json`) |
| کانتینر | ۵۹ تگ در ۴ فاز، ۱۴ تریگر مادر، ۵ بلاکر اجباری، الگوی «تگ مسیریاب» به‌جای ۴۰ تک‌تگ (`docs/04`, `data/tag-plan.csv`) |
| مقصدها | GA4 + BigQuery export + Clarity + import آفلاین سفارش/CRM (`docs/05`) |
| ابزار | shim قابل نصب (۲ روزه) + Validator خودکار QA + DDL انبار (`snippets/`, `data/warehouse-ddl.sql`) |
| حاکمیت | ۱۸ تست الزامی، SLO کیفیت داده، نقشه‌ی راه ۸ هفته‌ای (`docs/06`) |

## سه عددی که تا ۹۰ روز آینده باید عوض شوند
1. **تعیین‌تکلیف بودجه:** CAC مشتریِ «تأییدشده» به تفکیک کانال (این امروز وجود ندارد).
2. **بازگشت تقاضای سرکوب‌شده:** سبدِ «ناموجود/قیمت‌پنهان» که امروز بی‌صدا می‌میرد → فرم «خبرم کن» + استعلام خودکار.
3. **Attach-Rate:** نسبت فروش قطعات پروتز به فیکسچر برای هر «سیستم» — سودِ ۵ ساله‌ی هر مشتری در همین عدد است؛ کمپین‌ها باید بر اساس آن هدف بگیرند، نه بر اساس فروش فیکسچر.

## چهار باگی که امروز داده و فروش را می‌سوزاند (رفعشان یک‌ساعته است)
| مورد | اثر |
|---|---|
| منوی «اقساطی» → `/leasing-404/` | یک مسیر تبدیل پول‌سازِ مرده؛ ترافیک کمپینی سوخت می‌شود |
| `http://club.titana.ir` (بدون TLS) | شکستن کوکی/لینکر بین دامنه‌ای + هشدار مرورگر موبایل |
| رندر `{Balance}` در کارت محصولات | نشانه‌ی متغیر وصل‌نشده → اگر dataLayer از همین DOM خوانده شود، داده آلوده است |
| `Value=28` مشترک برای برند DRI و Naxis در داده‌ی فرم | اگر فیلتر/تحلیل بر این کلید سوار شود، دو برند با هم شمرده می‌شوند |

## ریسک اصلی که باید بپذیرید
بدون اضافه‌کردن **یک فیلد** به فرم ثبت‌نام — «چند ایمپلنت در ماه می‌کارید؟» — هیچ تگی در جهان به شما نمی‌گوید کدام کانال مشتریِ بزرگ می‌آورد. این یک‌خطی‌ترین و پربازده‌ترین درخواست ما از تیم فنی است.
