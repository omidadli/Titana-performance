# پیوست — واژه‌گان داده (Data Dictionary)

> مرجع فنی تیم: اسم رویدادها، اسکیم dataLayer، پارامترها، استنداردها. هر تغییر در این فایل = تغییر در همه‌جا؛ فقط با ثبت در «دفتر تغییرات GTM».

---

## 1) فهرست 6 رویداد اصلی (فاز ۱)

| رویداد | محل ریزش | مقصد | Key Event در GA4 |
|---|---|---|---|
| `view_item` | PDP + صفحه‌ی `/model/...` | GA4 | نه |
| `add_to_cart` | پس از انتخاب سایز/مدل و افزودن | GA4 | نه |
| `begin_checkout` | ورود به چک‌اوت | GA4 | **بله** |
| `purchase` | صفحه‌ی موفقیت پرداخت | GA4 + یکتانت + تپ‌سول | **بله** |
| `generate_lead` | 8 مسیر لید (زیر) | GA4 + یکتانت + تپ‌سول | **بله** |
| `search` | صفحه‌ی نتیجه‌ی جستجوی داخلی | GA4 | نه |

> `remove_from_cart` و `add_payment_info`: **اختیاری**، فقط اگر در فاز ۳ به گلوگاه مربوطه رسیدیم. اضافه‌کردن بدون نیاز = جریمه‌ی پیچیدگی.

## 2) اسکیم dataLayer (JSON)

### 2.1 `view_item` (PDP و صفحه‌ی مدل/سایز)
```json
{
  "event": "view_item",
  "ecommerce": {
    "currency": "IRR",
    "value": 74000000,
    "items": [{
      "item_id": "505",
      "item_name": "فیکسچر ایمپلنت سوون مدیکس (Sewon Medix)",
      "brand": "Sewon Medix",
      "price": 74000000,
      "variant": "4.0x10"
    }]
  },
  "page_type": "pdp"
}
```
- `price` همیشه به **ریال** (تومان × 10). GA4 currency = `IRR`.
- صفحه‌ی `/model/506` هم دقیقاً همین رویداد را می‌ریزد + `page_type: "model"`.
- `brand` از فیلد برند محصول (زیر‌سیستم مثل SLA در `variant`).

### 2.2 `add_to_cart` / `remove_from_cart`
```json
{
  "event": "add_to_cart",
  "ecommerce": {
    "currency": "IRR",
    "value": 148000000,
    "items": [{ "item_id": "505", "item_name": "...", "brand": "Sewon Medix", "price": 74000000, "quantity": 2, "variant": "4.0x10" }]
  }
}
```
- `value` = ارزش **کل سبد** بعد از افزودن (GA4 standard).

### 2.3 `begin_checkout`
```json
{
  "event": "begin_checkout",
  "ecommerce": {
    "currency": "IRR",
    "value": 148000000,
    "items": [ "...همان آرایه‌ی سبد..." ]
  }
}
```

### 2.4 `purchase` (فقط در صفحه‌ی موفقیت پرداخت)
```json
{
  "event": "purchase",
  "ecommerce": {
    "transaction_id": "WB-102345",
    "currency": "IRR",
    "value": 148000000,
    "items": [ "...همان آرایه‌ی سبد..." ]
  }
}
```
- `transaction_id` = شماره‌ی سفارش وب‌بیت (برای دی‌دپلیکیت). **اجباری.**
- `value` = مبلغ نهایی پرداخت‌شده (پس از هر تخفیف).

### 2.5 `generate_lead` (8 مسیر)
```json
{
  "event": "generate_lead",
  "lead_method": "price_list",
  "lead_item_id": "505",
  "lead_item_name": "فیکسچر ... (Sewon Medix)",
  "lead_brand": "Sewon Medix",
  "user_id": "09121234567"
}
```
**مقادیر مجاز `lead_method` (فقط این 8، چیز دیگر نه):**

| مقدار | یعنی |
|---|---|
| `price_list` | دانلود لیست قیمت (دکمه روی PDP) |
| `catalog` | دانلود کاتالوگ PDF |
| `form` | ارسال فرم‌ها (تماس، نظرات، استعلام قیمت) |
| `whatsapp` | کلیک دکمه/لینک واتساپ |
| `telegram` | کلیک تلگرام |
| `bale` | کلیک بله |
| `call` | کلیک `tel:` |
| `chatbot` | شروع مکالمه با «تینا» / ارجاع bot به تماس |

- `user_id` = موبایل نرمال‌شده (فقط در مسیرهایی که شماره داریم: `form`, `whatsapp` با لینک شمار‌دار، `call` اگر تماس برقرار شد و ثبت شد).
- `lead_item_id/name/brand` = محصولی که کاربر روی صفحه‌ی آن لید داده (برای ریتارژتینگ برندِ مورد علاقه — فاز ۴).

### 2.6 `search`
```json
{
  "event": "search",
  "search_term": "point sla 4mm",
  "num_results": 12
}
```

## 3) استندارد user_id (فاز ۱، پیش‌نیاز فاز ۴)

- **فرمت:** فقط 11 رقم، بدون پیشوند/نقطه/فاصله (نمونه: `09121234567`).
- **کجا می‌افتد:** فرم‌ها (فیلد موبایل)، و در هر لیدی که شماره ثبت می‌شود.
- **چرا:** ایمپورت تبدیل آفلاین GA4 (فاز ۴) فقط روی `user_id` می‌چرخد. بدون آن، نیمه‌ی درآمد نامرئی می‌ماند.
- **حریم خصوصی:** در GA4 به‌صورت خام می‌ماند (داخل پراپرتی ما)؛ در هیچ جایی عمومی نیست.

## 4) استندارد UTM و نام‌گذاری کمپین (فاز ۴، اجباری)

الگو: `ykt_{{کمپین}}_{{خلاقیت}}_{{جاگیر}}` / `tsc_{{کمپین}}_{{خلاقیت}}_{{جاگیر}}`

نمونه‌ی کامل URL:
```
https://www.titana.ir/product/644/...?utm_source=yektanet&utm_medium=cpc&utm_campaign=ykt_tstrong_pkg100&utm_content=creative-02&utm_term=pkg100-40free
```

| پارامتر | قاعده |
|---|---|
| `utm_source` | `yektanet` / `tapsell` / `organic` / `whatsapp` / `telegram` ... |
| `utm_medium` | `cpc` / `display` / `cpa` / `sms` / `referral` |
| `utm_campaign` | الگوی بالا (حداکثر 3 بخش، حروف کوچک، بدون فاصله) |
| `utm_content` | شناسه‌ی خلاقیت (creative-01, creative-02, ...) |

**قاعده‌ی طلایی:** هر کمپین بدون UTM = بودجه‌ای بدون ردپا. در چک‌سلامتی ماهانه، کمپین‌های بدون UTM صفر tolerated.

## 5) سوابق تصمیم (چرا این شکل است)

| تصمیم | دلیل |
|---|---|
| فقط 6 رویداد | B2B با ترافیک متوسط؛ رویداد اضافی = هزینه‌ی نگهداری + گزارش شلوغ. افزودن فقط با «سوال بیزینسی واقعی» (قاعده‌ی فاز ۵) |
| قیمت به ریال + `IRR` | قیمت‌ها ده‌ها میلیون تومان؛ ریال = بدون گرد کردن |
| `purchase` فقط در صفحه‌ی موفقیت | جلوگیری از شمرده‌شدن پرداخت‌های شکست‌خورده |
| GTM تنها لایه‌ی تگ | تغییرات بدون دخالت در کد سایت؛ قابلیت Preview/Debug |
| `generate_lead` یک رویداد + پارامتر (نه 8 رویداد) | گزارش‌پذیری: یک رویداد، 8 برش |
